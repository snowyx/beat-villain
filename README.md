## ⚡ 60 秒跑起来（给评委 / 第一次看的人）

本项目**零构建、零数据库**，只需本机装了 **Node ≥ 18**（含 `npm`）和 **Python 3**（仅用来起一个静态服务器，几乎所有 Mac/Linux 自带）。

打开**两个终端**，分别复制粘贴下面两段即可：

**终端 1 — 启动房间服务（后端）**

```bash
cd server
npm install
npm start
```

看到 `listening on ws://0.0.0.0:8080` 就说明后端好了，这个终端保持开着别关。

**终端 2 — 启动页面（前端）**

```bash
cd app
python3 -m http.server 5173
```

然后浏览器打开 **<http://localhost:5173/>** —— 开玩！

> 没有 Python？任意静态服务器都行，例如 `npx serve app -l 5173` 或 VS Code 的 Live Server 插件。前端默认自动连本机后端 `ws://localhost:8080`，无需任何配置。

## 🎬 30 秒 Demo 脚本（怎么演示最出彩）

这是个**双人**应用，但一个人用**两个浏览器标签页**就能完整演示「苦主 + 神婆」实时同步。按这个顺序走，30 秒就能让人笑出来：

| 步骤 | 操作 | 看点 |
| --- | --- | --- |
| 1 | **标签页 A**（苦主）打开 <http://localhost:5173/>，在「开坛立牌」给小人起花名 | 试着输入真名（如「张三」）会被**当场拦截**，提示填花名；点 🎲 一键随机花名 |
| 2 | 勾几个罪状（甩锅侠 / 画饼大师…），点「🔥 开坛」 | 进入邀请页，拿到**坛号**和**二维码** |
| 3 | 点「📋 复制邀请链接」，**新开标签页 B**（神婆）粘贴打开 | B 页进入「神婆入坛」，点「进坛代打」 |
| 4 | 回标签页 A，点「🧙 开始念咒」，选 **普通话 / 粤语 / 英语** | 浏览器**三语朗读开打令**（粤语同屏显示原文）|
| 5 | 两个标签页**随便哪个点小人抽鞋** | 另一个标签页的小人**实时同步**掉血、弹跳、表情渐崩（嚣张→懵逼→冒烟）|

> **录屏建议**：横向并排摆两个标签页，让观众一眼看到「A 点一下、B 同步动」的实时效果——这是最抓眼球的瞬间。

## 🕹️ 玩法介绍（完整仪式闭环）

1. **开坛立牌** —— 苦主创建房间，给小纸人起「花名」（输入即时拦截真实姓名格式，引导填花名/代号），勾选罪状标签（抢功劳 / 甩锅侠 / 阴阳怪气 / 已读不回 / 画饼大师 / 卷王本卷）。
2. **请神婆** —— 生成邀请链接与二维码，神婆（或围观群众）扫码入场，双角色实时同房。
3. **三语念咒** —— 开打前选咒语语言：普通话 / 粤语 / 英语。音频走「mp3 优先 → Web Speech 朗读 → 文字兜底」三级回退；选粤语走 Web Speech 时同屏显示粤语原文。
4. **抄鞋开打** —— 小人挂在屏幕中央，点击/滑动即「抄鞋」抽打。点小人的头/肚子/腿有不同痛苦反应（晃头冒金星 / 弓身捂肚 / 跳脚）并蹦出拟声词。纸人物理弹跳、表情随鞋数渐崩（嚣张 0–5 → 懵逼 6–10 → 冒烟 11–17 → 化灰 18）。后端是单一事实源，任一端落鞋，另一端实时同步计数。
5. **化灰仪式** —— 打满 18 鞋，小人原地化灰：祥云消散 + 赛博纸钱，全无血腥。
6. **转运签** —— 自动出签文（宜 / 忌 / 贵人），生成一张港式符咒分享图，长按或一键保存/分享。

## 🛠️ 常见问题排查

- **小人点了没反应 / 两个标签页不同步？** 多半是后端没起或连不上。确认终端 1 显示了 `listening on ws://0.0.0.0:8080`，且浏览器开的是 `http://localhost:5173`（不是直接双击 `index.html` 打开 `file://`——那样连不上后端）。
- **粤语没声音？** 很多电脑系统没装粤语语音，这是浏览器 Web Speech 的限制，会自动降级为**文字显示**（咒语原文照样出现在屏幕上）。想要真人质感配音见下方「三语配音」。
- **端口被占用？** 后端用 `PORT=9000 npm start` 换端口，同时在浏览器控制台执行 `localStorage.setItem('WS_URL','ws://localhost:9000')` 让前端连过去；前端静态端口把 `5173` 改成别的即可。

## 🔊 三语配音（可选，默认不需要）

默认开箱即玩：念咒直接走浏览器 **Web Speech**（普 `zh-CN` / 粤 `zh-HK` / 英 `en-US`），无需任何 key。

想要高质量 **ElevenLabs** 配音（P1 升级）：

```bash
export ELEVENLABS_API_KEY=你的key      # key 仅从环境变量读，绝不写进代码
node scripts/generate-audio.mjs        # 生成 3 个 mp3 到 assets/audio/
```

再把 `app/js/config.js` 里 `AUDIO_MANIFEST` 对应语言项改成 `true`，前端就会优先播放 mp3。生成的 mp3 已被 `.gitignore` 忽略、不会提交入库。

## 🌐 日后部署上线（传 GitHub 后让评委直接点开玩）

前端是纯静态页，后端需要一个支持 WebSocket 的运行环境：

1. **前端**：把 `app/` 目录托管到任意静态平台（GitHub Pages / Vercel / Netlify / OSS 均可）。
2. **后端**：把 `server/` 部署到支持 WebSocket 的容器 / VM（Railway / Render / Fly.io / 自有服务器）。
3. **让前端连上线上后端**：把 `app/js/config.js` 里 `WS_URL` 的占位 `wss://REPLACE_WITH_ROOM_SERVER_HOST` 改成你的后端地址（如 `wss://room.yourhost.com`）；临时测试也可在浏览器控制台执行 `localStorage.setItem('WS_URL','wss://room.yourhost.com')`。
4. 部署完把在线链接填回本文件顶部的 TODO 处，评委点开即玩。

> 注意：GitHub Pages 只能托管静态前端，**托管不了 WebSocket 后端**。所以线上完整体验需要前端 + 后端两处分别部署。若只想给评委看效果而不部署后端，录一段 demo 视频是最省事的保底方案。

## 🏗️ 技术架构

- **前端**：纯静态 H5 竖屏单页（375px 小程序骨相），原生 ES Module，零构建。六个流程态（开坛 / 邀请 / 念咒 / 开打 / 化灰 / 转运签）同页切换，以后端快照的 `phase` 为唯一界面路由依据。
- **实时房间**：单文件 Node `ws` 内存房间服务（`server/room-server.js`）作**单一事实源**。所有改变共享进度的动作（落鞋 / 切咒语 / 化灰 / 抽签 / 进出房）只经后端改内存并广播，前端不自行推进共享进度。首帧契约 `hello → hello_ok{clientId}`；落鞋高频路径只发 `hit` 增量帧，前端对 `hits` 取 `Math.max` 单调防回退；房满为两名已认领成员，带旧 `clientId` 重连在 60s 窗口内认领原槽。
- **配音**：三级回退 —— mp3 优先 → Web Speech API（zh-CN / zh-HK / en-US）→ 文字兜底；音频由用户手势触发。ElevenLabs 为可选的开发期预生成脚本，运行时零依赖。
- **分享图**：canvas 2D 绘制港式符咒分享图，保存 / 分享判定顺序 `navigator.canShare({files}) → a[download] → 提示长按`。
- **同步**：WebSocket 双角色实时同步（苦主 + 神婆）。
- **二维码**：离线 vendored `qrcode.min.js`（UMD），不走 npm 运行时依赖。

## 🛡️ 合规说明（三条红线）

本作品定位为「民俗文化体验与解压娱乐」，严守三条不可破例的红线：

1. **不诅咒真人** —— 花名输入在提交前经 `app/js/compliance.js` 启发式拦截疑似真实姓名（姓氏表 + 姓+称谓），命中即阻止提交且不发起任何网络请求；常驻「一键随机花名」逃生口兜底。语音只朗读固定咒语，不朗读花名；后端不存任何真实身份信息。
2. **无血腥暴力** —— 小人仅为卡通纸片人；化灰的唯一表现是祥云消散 + 赛博纸钱，无伤口、无血液、无断肢；朱砂红只用于符咒与 UI，绝不表现血。
3. **民俗定位标注** —— 可见处标注「打小人」为粤港澳民间习俗（惊蛰日鹅颈桥下最盛），定位「民俗数字化体验」；页脚常驻「本应用为民俗文化体验与解压娱乐」；canvas 分享图保留合规小字，确保传播物也带声明。

## 🤖 本项目全程用 Kiro 完成

本项目从立意到交付，全程在 Kiro 里用 **Spec / Steering / Hooks** 三大能力完成，证据都留在 `.kiro/` 目录：

- **Spec 驱动**：需求、设计、任务三份文档位于 `.kiro/specs/kick-bad-guy/`（`requirements.md` 用 EARS 写用户故事与验收标准，`design.md` 定架构 / 房间状态机 / 音频方案 / 协议，`tasks.md` 拆成有序任务清单），并附 `design-review.*` 设计评审裁决。Kiro 按 tasks 逐项实现，spec 本身即参赛材料。
- **Steering**：`.kiro/steering/民俗合规.md` 与 `.kiro/steering/视觉风格.md` 作为常驻规则，让每一轮代码生成自动遵守合规三红线与港式霓虹纸扎视觉风格，无需每次重复叮嘱。
- **Hooks**：`.kiro/hooks/前端改动跑冒烟测试.kiro.hook` 在前端源码保存时自动触发本地冒烟测试（合规纯函数单测 + 后端房间服务单测），把回归校验挂进开发闭环。

想看开发过程，直接翻 `.kiro/` 目录即可：specs 三文档记录了「想清楚再动手」的决策链，steering 两文档是贯穿始终的护栏，hook 是自动化的质量关卡。这正是 Kiro「规格先行、规则常驻、自动校验」协作方式的完整体现。
