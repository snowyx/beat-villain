# 赛博打小人 · Cyber Beat the Villain

> 鹅颈桥下，赛博开坛——香港非遗民俗「打小人」，手机一扫，苦主在线供奉，神婆远程代打，三语咒语（普/粤/英）环绕立体输出。

参赛作品 · Kiro 鬼点子计划（InfoQ × 亚马逊云科技）。把流行于粤港澳的民间仪式「打小人」做成一个可分享的多人解压仪式应用：不写真实姓名、不见血、港式霓虹纸扎卡通风，主打「民俗体验 + 情绪解压 + 社交整活」。

---

## 玩法介绍

一条仪式闭环，两个人就能开坛：

1. **开坛立牌** —— 苦主创建房间，给小纸人起个「花名」（输入即时拦截真实姓名格式，引导填花名/代号），勾选罪状标签（抢功劳 / 甩锅侠 / 阴阳怪气 / 已读不回 / 画饼大师 / 卷王本卷）。
2. **请神婆** —— 生成邀请链接与二维码，神婆（或围观群众）扫码入场，双角色实时同房。
3. **三语念咒** —— 开打前选咒语语言：普通话 / 粤语 / 英语。音频走「mp3 优先 → Web Speech 朗读 → 文字兜底」三级回退；选粤语走 Web Speech 时同屏显示粤语原文。
4. **抄鞋开打** —— 小人挂在屏幕中央，点击/滑动即「抄鞋」抽打。纸人物理弹跳、表情随鞋数渐崩（嚣张 0–21 → 懵逼 22–43 → 冒烟 44–87 → 化灰 88）。后端是单一事实源，任一端落鞋，另一端实时同步计数。
5. **化灰仪式** —— 打满 88 鞋，小人原地化灰：祥云消散 + 赛博纸钱，全无血腥。
6. **转运签** —— 自动出签文（宜 / 忌 / 贵人），生成一张港式符咒分享图，长按或一键保存/分享。

## 本地运行（确切命令）

本项目纯静态前端 + 单文件 Node WebSocket 后端，零构建。需本机 Node ≥ 18。

### 1. 后端房间服务（WebSocket）

```bash
cd server
npm install
npm start
```

默认监听 `0.0.0.0:8080`（可用环境变量覆盖，如 `PORT=9000 npm start`）。

### 2. 前端（静态页）

另开一个终端：

```bash
cd app
python3 -m http.server 5173
```

然后浏览器打开 <http://localhost:5173/>。前端默认连本机房间服务 `ws://localhost:8080`。

> **线上部署**：把 `app/js/config.js` 里 `WS_URL` 的占位 `wss://REPLACE_WITH_ROOM_SERVER_HOST` 改成实际房间服务地址；或在浏览器控制台执行 `localStorage.setItem('WS_URL','wss://你的房间服务')` 临时覆盖。前端可托管于任意静态服务器，房间服务需部署在支持 WebSocket 的运行环境（容器/VM）。

### 三语配音（可选，默认不需要）

默认 `AUDIO_MANIFEST` 三项皆为 `false`，念咒直接走 Web Speech / 文字兜底，开箱即玩。
如需高质量 ElevenLabs 配音：`export ELEVENLABS_API_KEY=你的key` 后运行 `node scripts/generate-audio.mjs` 预生成三个 mp3，再把 `app/js/config.js` 的 `AUDIO_MANIFEST` 对应项置 `true`。key 仅从环境变量读，绝不入库；生成的 mp3 被 `.gitignore` 忽略、不提交。

### 跑测试

```bash
cd server && npm test                       # 后端房间逻辑 + 集成全链路
node --test app/js/compliance.test.js       # 前端花名合规纯函数单测
```

## 技术架构

- **前端**：纯静态 H5 竖屏单页（375px 小程序骨相），原生 ES Module，零构建。六个流程态（开坛/邀请/念咒/开打/化灰/转运签）同页切换，以后端快照的 `phase` 为唯一界面路由依据。
- **实时房间**：单文件 Node `ws` 内存房间服务（`server/room-server.js`）作**单一事实源**。所有改变共享进度的动作（落鞋/切咒语/化灰/抽签/进出房）只经后端改内存并广播，前端不自行推进共享进度。首帧契约 `hello → hello_ok{clientId}`；落鞋高频路径只发 `hit` 增量帧，前端对 `hits` 取 `Math.max` 单调防回退；房满为两名已认领成员，带旧 `clientId` 重连在 60s 窗口内认领原槽。
- **配音**：三级回退 —— mp3 优先 → Web Speech API（zh-CN/zh-HK/en-US）→ 文字兜底；音频由用户手势触发。ElevenLabs 为可选的开发期预生成脚本，运行时零依赖。
- **分享图**：canvas 2D 绘制港式符咒分享图，保存/分享判定顺序 `navigator.canShare({files}) → a[download] → 提示长按`。
- **同步**：WebSocket 双角色实时同步（苦主 + 神婆）。
- **二维码**：离线 vendored `qrcode.min.js`（UMD），不走 npm 运行时依赖。

目录：`app/`（前端）、`server/`（房间服务 + 测试）、`scripts/`（配音预生成脚本）、`assets/audio/`（mp3 占位目录）、`.kiro/`（Kiro Spec / Steering / Hooks）。

## 合规说明（三条红线）

本作品定位为「民俗文化体验与解压娱乐」，严守三条不可破例的红线：

1. **不诅咒真人** —— 花名输入在提交前经 `app/js/compliance.js` 启发式拦截疑似真实姓名（姓氏表 + 姓+称谓），命中即阻止提交且不发起任何网络请求；常驻「一键随机花名」逃生口兜底。语音只朗读固定咒语，不朗读花名；后端不存任何真实身份信息。
2. **无血腥暴力** —— 小人仅为卡通纸片人；化灰的唯一表现是祥云消散 + 赛博纸钱，无伤口、无血液、无断肢；朱砂红只用于符咒与 UI，绝不表现血。
3. **民俗定位标注** —— 可见处标注「打小人」为粤港澳民间习俗（惊蛰日鹅颈桥下最盛），定位「民俗数字化体验」；页脚常驻「本应用为民俗文化体验与解压娱乐」；canvas 分享图保留合规小字，确保传播物也带声明。

## 本项目全程用 Kiro 完成

本项目从立意到交付，全程在 Kiro 里用 **Spec / Steering / Hooks** 三大能力完成，证据都留在 `.kiro/` 目录：

- **Spec 驱动**：需求、设计、任务三份文档位于 `.kiro/specs/kick-bad-guy/`（`requirements.md` 用 EARS 写用户故事与验收标准，`design.md` 定架构/房间状态机/音频方案/协议，`tasks.md` 拆成有序任务清单），并附 `design-review.*` 设计评审裁决。Kiro 按 tasks 逐项实现，spec 本身即参赛材料。
- **Steering**：`.kiro/steering/民俗合规.md` 与 `.kiro/steering/视觉风格.md` 作为常驻规则，让每一轮代码生成自动遵守合规三红线与港式霓虹纸扎视觉风格，无需每次重复叮嘱。
- **Hooks**：`.kiro/hooks/前端改动跑冒烟测试.kiro.hook` 在前端源码保存时自动触发本地冒烟测试（合规纯函数单测 + 后端房间服务单测），把回归校验挂进开发闭环。

想看开发过程，直接翻 `.kiro/` 目录即可：specs 三文档记录了「想清楚再动手」的决策链，steering 两文档是贯穿始终的护栏，hook 是自动化的质量关卡。这正是 Kiro「规格先行、规则常驻、自动校验」协作方式的完整体现。
